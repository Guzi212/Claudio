# Claudio 路线图

> 最近更新：2026-11-24（阶段 1 内置大脑与常驻主持人清理完成）
>
> 这份文档管方向和优先级；具体技术任务记在 [`dev-plan.md`](dev-plan.md)。

## 定位

**给 AI Agent 用的本地音乐播放器。** Agent 负责选歌和主持，Claudio 负责找歌、出声、显示。

- 目标用户：现阶段是自己玩过 AI、手里有 Agent 的用户；普通用户放到远期（见文末「远期设想」）
- 分发：桌面安装包；音源由用户自己扫码登录
- 不做：Claudio 自己当大脑选歌（internal 冻结，阶段 1 存档移除）；只给元数据、拿不到直链的平台（Apple Music / Spotify 等，理由见 dev-plan 阶段二）

## 现状差距（2026-11-23 盘点）

| 差距 | 现状 | 对用户的影响 |
| --- | --- | --- |
| 还没有用户反馈 | 已有 issue 模板和设置页反馈入口（PR #49、#50），反馈仍散在仓库外 | 不知道用户真正卡在哪 |
| 安装门槛高 | 要同级克隆 KuGouMusicApi、NeteaseCloudMusicApiEnhanced、QQMusicApi + Python venv，占 3 个端口，Node ≥ 22.12 | 普通用户基本装不上 |
| Agent 接入靠粘贴指令 | README 一段 prompt 发给 Grok Bot | 普通用户手里没有 Agent |
| 接口无版本 | README 点歌指令就是事实上的公开契约 | 改一次就打断别人的 bot |
| 前端巨石 | `pwa/views/player.js` 2075 行、`styles.css` 1685 行、3 套主题 | 改一处动全身 |
| 个人痕迹 | `state.db` 在仓库根；天气默认长沙；`user/` 品味语料 | 别人装上后行为奇怪 |

已解决的差距（发版、免责声明、许可证）见下方阶段 0。

## 已定决策（loic 2026-11-23）

| # | 问题 | 决定 |
| --- | --- | --- |
| D1 | 用户的 Agent 从哪来 | 现阶段用户自带 Agent；以后再做扫码对接聊天 bot。有确定的用户市场再内置大模型接口（见「远期设想」） |
| D2 | 音源服务怎么到用户机器上 | 安装器首次运行时从各上游仓库拉取；仓库和安装包不包含第三方音源服务代码 |
| D3 | 分发形态 | Electron 桌面安装包（`desktop/` 已有壳，托盘/开机自启/单点播放都已在桌面端做过） |

登录态预期：每人扫自己的账号，个人用量低，没有共享账号风控。网易云 MUSIC_U 长效；酷狗 cookie 会过期，已有低频续期；QQ 有手机端互踢和设备验证，做不到永不掉线。目标是「尽量长效 + 掉了界面上一键扫码恢复」。

## 远期设想（现在不做）

前提：有确定的用户市场（大量没有自己 Agent 的用户）。如果只是自己玩、当播放器用，这一块不做。

- **内置大模型接口**：设置里填一个模型 API key（如 DeepSeek），Claudio 直接调用它选歌，不依赖外部 Agent。
- **轻量本地 harness**：类似 personal agent 的入口，能长期积累听歌记忆、越来越懂用户。重新设计，不复活旧 internal 链路，
  可从 `archive/internal-brain` 存档里取可复用部分。

## 衡量

- 新用户从下载到出声 ≤ 10 分钟，全程不开终端（阶段 2 目标）
- 每月有效反馈 issue 数
- 音源掉登录后，用户能在界面里一键恢复
