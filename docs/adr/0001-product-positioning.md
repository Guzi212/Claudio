# ADR-0001：产品定位——给 AI Agent 用的播放器，先服务玩过 AI 的用户

- 状态：已采纳
- 日期：2026-11-23
- 决策人：loic

## 背景

Claudio 起步时是「个人 Claude AI 电台」：Claude 读品味语料、看时间和历史，自己选歌、自己播报（`CLAUDIO_BRAIN=internal`）。
后来选歌交给外部 Grok Bot，Claudio 默认只负责检索、直链和播放（`external`），但 internal 那套选歌链路
（`claude` / `context` / `router` / `scheduler` / `tts` / `dj` / `memory` / chat / studio，约 2700 行）一直留在主干。
结果是项目名、README、实际默认行为三处说法不一致，维护成本落在一条默认不跑的路径上。

同时项目开始被身边的人使用，用户不再只有作者本人。

## 决策

1. **定位**：Claudio 是给 AI Agent 用的本地音乐播放器。Agent 负责选歌和主持，Claudio 负责找歌、出声、显示。
2. **目标用户分两步**：
   - 现阶段：自己玩过 AI、手里有 Agent 的用户。Claudio 只提供播放入口，音源由用户自己扫码登录。
   - 远期（有确定的用户市场才做；只当个人播放器用则不做）：普通用户。内置一个大模型接口（如填 DeepSeek API key），由本地轻量 harness 完成选歌和播放，没有自己 Agent 的人也能用。
3. **分发形态**：桌面安装包（Electron）。音源服务由安装器首次运行时从各上游官方仓库拉取，安装包本身不包含第三方音源服务代码。
4. **internal 大脑冻结**：不再给 internal 选歌加功能；在路线图阶段 1 打存档 tag 后从主干移除。
   远期的内置 harness 重新设计，可从存档里取可复用部分（DeepSeek 调用、品味记忆）。
   常驻主持人（`server/dj/resident.js`，external 下也会补歌）单独评估去留。

## 后果

- 「装得上、不掉线、出得了声」成为最高优先级；所有需要终端或 `.env` 的功能都要补界面入口。
- 对外接口（外部点歌 API、搜索、健康检查）成为公开契约，需要版本化。
- 当前 README 的「AI 一键安装」面向会用 Claude Code / Codex 的用户，和现阶段目标用户一致，
  桌面安装包落地前保留。
- 登录态预期：每人扫自己的账号，个人用量低，不存在共享账号风控；目标是「尽量长效 + 掉了界面上一键扫码恢复」，
  不追求永不掉线（QQ 存在手机端互踢、设备验证）。
- 第三方音源服务由用户自行获取和登录，Claudio 不内置、不托管。
